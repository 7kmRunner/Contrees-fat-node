# BeTree checkpoint 修复与同容量对照

本轮修复独立控制器串行物化路径遗漏 `new_checkpoint` 的问题：完成更新后，
先以本次版本重建，再将旧路径与中间树外壳交给 GC，最后发布新根。批量合并路径
原先已有 checkpoint，本轮没有改变其算法。

专项测试现在覆盖 full/partial × 串行物化/批量合并四种组合，明确断言重建发生
一次、重建类型正确。未更新叶的物理地址在 partial 中保持、在 full 中替换；
GC 排空后仍可读出该叶的基础值与历史值。旧版本范围快照保持 240 个基础键，
新版本包含 369 个键。测试使用人工构造的阈值边界树，不能替代长期自然增长实验。

BeTree 24 组功能配置及四种 checkpoint 专项、其它三棵树并行回归均通过。
BeTree 在 mimalloc 和系统分配器下的 UBSan 均通过。ASan/TSan 仍按既定决定搁置。

## 测量口径

macOS ARM64，Apple clang 17，mimalloc，C++20/O3/NDEBUG。
100,000 初始键、100,000 操作、4 个提交客户端，GC 开启。
初始 BeTree boundary 参数为 2。每配置预热一次，正式测量三次，交替配置顺序。
60 配置共 180 条正式结果，均完成参考键值与 GC 检查。

新增 SeqCow slots=4/8 对照，以下将 SeqCow 与单 worker batch 按相同槽数比较。
耗时为三次中位数，RSS 为进程峰值中位数。SeqCow context 数量 65536，新控制器
队列 4096；发布和回收频率也不同，内存收益包含控制器差异。

同容量下所有这些 batch 配置都更省峰值内存，但耗时更长。之前 Batch8 相对
Seq2 的优势属于不同容量配置的比较，不能解释为新架构单独带来的吞吐收益。
本轮修复针对 checkpoint 正确性，不应把跨轮耗时变化解释成该修复的优化效果。
普通性能矩阵未记录 checkpoint 次数，不能据此判断重建触发频率。

更多 worker 未呈现稳定吞吐扩展。后续性能工作应优先分析热点造成的短批次、
协调线程分组及版本发布开销；论文规模和不同平台验证仍未完成。

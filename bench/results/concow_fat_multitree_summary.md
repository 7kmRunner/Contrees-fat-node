# 四棵树的有序批次 fat-node 第一阶段总结

BeTree 最新验收已补齐串行物化 checkpoint 和严格的 full/partial 断言，见
[180 条同容量实验](concow_betree_checkpoint_fixed_summary.md)。该实验显示 BeTree
在相同槽数下峰值 RSS 降低 26.5%–56.9%，但耗时更长；本文下方不同容量的
历史比较不作为架构吞吐优势的证据。

四棵树现在共用一个控制器 `lib/conctrl/concow_fat.hpp`。共同协议是：按 ticket
取得连续批次，按目标叶分组，不同叶可由 worker 并行追加或准备私有替换，随后由
协调线程一次合并该轮所有受影响路径，最后统一发布 root/version 并交给 reader
version GC 回收。`concow-fat` 已作为独立调度器接入主程序。

| 树 | 复用的共同部分 | 树特有的合并工作 | 第一阶段状态 |
|---|---|---|---|
| B+Tree | 分组、叶物化、共享路径、GC | 多叶分裂向根级联合并 | 完成 |
| ART | 同上 | 压缩字节前缀，Node4/16/48/256 扩容 | 完成 |
| AERT | 同上 | tagged pointer、隐式四位前缀、上下半字节节点 | 完成 |
| BeTree | 同上 | elastic boundary、子树高度、full/partial checkpoint | 完成 |

ART、AERT、BeTree 使用同一套 100,000 初始键、100,000 操作、4 客户端实验。
以下取单 worker、slots=2，对照各自 SeqCow slots=2；数字为三次中位数。B+Tree
早期矩阵使用 10,000 键和 30,000 次更新，不能与这三棵树直接横向排名，详见其
[独立报告](concow_fat_btree_summary.md)。

| 树 | 负载 | 固定旧快照 | Seq ms / RSS MiB | 新架构 ms / RSS MiB | RSS 降幅 |
|---|---|---:|---:|---:|---:|
| ART | uniform | 0 | 5.96 / 52.80 | 8.00 / 23.05 | 56.3% |
| ART | hot | 1 | 15.41 / 184.00 | 16.34 / 44.30 | 75.9% |
| ART | insert | 0 | 32.40 / 206.14 | 15.15 / 32.05 | 84.5% |
| AERT | uniform | 0 | 5.62 / 33.38 | 9.00 / 23.41 | 29.9% |
| AERT | hot | 1 | 8.60 / 64.67 | 16.59 / 30.89 | 52.2% |
| AERT | insert | 0 | 20.65 / 77.02 | 18.56 / 32.81 | 57.4% |
| BeTree | uniform | 0 | 17.66 / 43.72 | 23.82 / 20.44 | 53.2% |
| BeTree | hot | 1 | 10.90 / 74.95 | 40.61 / 43.12 | 42.5% |
| BeTree | insert | 0 | 15.58 / 56.59 | 22.82 / 24.25 | 57.1% |

结论比较稳定：新架构的主要收益是减少旧路径和分配流量，从而降低峰值内存；
ART/AERT 插入还获得吞吐收益。普通更新中，协调、分组和逐轮发布成本经常高于
节省的路径复制，因此 SeqCow 仍更快。BeTree 使用 slots=8 时，均匀更新和插入
可在峰值 RSS 仍降低 51.6%--64.6% 的同时达到 1.04--1.28x 加速，但热点更新
依然慢。更多 worker 大多没有更快；现有多 worker 结果证明并发正确性，不证明
吞吐扩展。

验证包括每棵树 24 组 slots/workers/物化模式、ticket 参考模型、旧快照、范围
查询、worker 异常不发布、GC 排空，以及各树的结构专项测试。四棵树均通过优化
构建，mimalloc 和系统分配器 UBSan。ASan/TSan 因当前环境问题按既定决定搁置，
不记为通过。正式 x86-64 论文规模实验仍待补。
